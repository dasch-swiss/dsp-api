## Deferrals

- Phase 2 review, `scope`: the dune reviewer flagged that `slice/ingest/domain` and `slice/ingest/repo` import each other (`AssetInfo`, `Sha256Hash` and the service traits live in `repo` but are domain types). The plan fixes the layout and the "move unchanged" rule, so sorting the types, or adding a package-dependency check, is for the final review or a follow-up.
- Phase 4 review (dune), `scope`: every ingest rest-service method wraps its body in `ingestExecutor.run` by hand, as the plan specifies; a new method that forgets it runs on the default executor with no error. Moving `run` to one choke point (the ingest server-endpoint registration) or adding a check that every ingest rest-service method calls it is for the final review or a follow-up. Related suggestion: name the permit owners (`CommandExecutor`, `FileChecksumService`, the BagIt call sites) in `docs/development`, and move the domain-level BagIt permits behind an infrastructure port.

## Deviations

- Phase 3, proposed (plan text): ingest scope refusals stay `401` with the standalone bodies (`{"reason":"Admin permissions required."}`, `{"reason":"No project access."}`), per the decided "identical error bodies". The Phase 3 checkboxes for `IngestMaintenanceEndpointsSpec` ("answer `403` without admin scope") and `IngestEndpointsE2ESpec` ("a token lacking write scope answers `403`") say `403`; the specs assert `401` (`00095dbb9`, `57e49e996`). Proposed: reword both checkboxes to `401`. Owner (2026-10-27): keep `401`, no reason to change; checkboxes reworded.
- Phase 3, proposed (security review, not applied): `/ingest/metrics` is public on the API port and serves the whole process's Prometheus data, which the metrics server otherwise serves only on its own port (`4824c3fc8`). Kept as decided ("/ingest/metrics serves the API's PrometheusPublisher"). Proposed for the owner: require admin scope on it, or have the proxy block it. Owner (2026-10-27): it was public before, it stays public.
- Phase 4, proposed (scala-zio and performance reviews, not applied): the decided wrapper `/bin/sh -c 'echo 1000 > /proc/self/oom_score_adj && exec "$0" "$@"'` fails closed: where `/proc/self/oom_score_adj` is not writable (read-only `/proc`, some hardened runtimes), `&&` stops before `exec`, so Sipi, ffmpeg and ffprobe never run and every ingest fails. Committed as decided (`cfa61c4f9`); it works in the temurin image as root and as uid 1000. Proposed for the owner: `echo 1000 > /proc/self/oom_score_adj 2>/dev/null; exec "$0" "$@"` (best effort), or keep fail-closed so a deployment without the OOM ordering is noticed.
